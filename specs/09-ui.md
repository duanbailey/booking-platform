# Web frontend

Screens and behaviour of the web app ([ADR 0012](../docs/adr/0012-provide-web-frontend.md)). The stories in [02-requirements.md](02-requirements.md) say what users can do; this file says how the app presents it. Each screen names the API operations it calls (`operationId` in [04-api.openapi.yaml](04-api.openapi.yaml)); rules are cited by ID (e.g. R4), as in tests.

Status: skeleton (2026-11-26). Items marked TODO are open; open decisions that block work are under "Decisions needed" in [plan/tasks.md](../plan/tasks.md).

# Principles

- The API is the source of truth for every rule; the app never re-implements a check to decide an outcome. It may check fields early (e.g. required fields) to help the user, but always shows the API's answer.
- Times are shown in local time with the zone named; the business's zone is the reference (R2).
- Browsers and accessibility as in [07-nfr.md](07-nfr.md): the last two versions of Chrome, Edge, Firefox and Safari (desktop and iOS), WCAG 2.2 AA.
- The access token is kept in memory only; the refresh token is an HttpOnly cookie the app never reads ([ADR 0013](../docs/adr/0013-refresh-token-in-httponly-cookie.md)). On load, the app calls `refreshToken` to find out whether the user is logged in. Refreshes run one at a time across all of the app's tabs (Web Locks API): two tabs sending the same cookie at once would look like reuse and revoke the login (ADR 0010; decided 2026-11-26).
- The app and the API share one origin (ADR 0012), so API calls use relative `/v1/...` URLs.

## Visitor (not logged in)

- **Login.** `login`.
- **Sign up.** `register`.
- **Forgot password.** `forgotPassword`. Says the same whether or not the account exists.
- **Reset password.** `resetPassword`.
- **Accept invite.** `acceptInvite`.

## Every logged-in user

- **Profile.** `getMe`, `updateMe`.
- **Change password.** `changePassword`.
- **Log out.** `logout`.

## Customer

- **Find a slot.** Reached through the business link `/b/{businessId}`; a visitor who isn't signed in is sent to log in or sign up, then back to the link (the API requires sign-in). `getBusiness`, `listServices`, `listStaff` (names), `listSlots`. Pages through the advance-booking window in ranges of up to 30 days (ADR 0005).
- **Book.** `createBooking`, with an `Idempotency-Key` per attempt (T29).
- **My bookings.** `listMyBookings`, `getBooking`.
- **Cancel or reschedule.** `cancelBooking`, `rescheduleBooking`; inside the cancellation window the actions are not offered (R4).

## Staff

- **My schedule.** `listBusinessBookings` (own bookings), `getBooking`, `getBookingHistory`.
- **Availability.** `getWeeklyAvailability`, `setWeeklyAvailability`, `listDateExceptions`, `setDateException`, `deleteDateException` (R6, R8).
- **Time off.** `listTimeOff`, `createTimeOff`, `deleteTimeOff` (R6).
- **Book on behalf of a customer.** `createBooking` with `customerEmail`; optional minimum-notice override (R3).
- **Cancel or reschedule own bookings.** `cancelBooking`, `rescheduleBooking`.

## Owner

Everything staff can do, for any staff member of the business, plus:

- **Business settings.** `getBusiness`, `updateBusinessSettings` (R3, R4, R8 settings). Shows the business link `/b/{businessId}` with a copy button.
- **Time zone.** `changeBusinessTimeZone`, `listTimeZoneChanges` (R2, R6).
- **Services.** `listServices`, `createService`, `getService`, `updateService`.
- **Staff.** `listStaff`, `addStaff`, `removeStaff` (R6), `setStaffServices`, `resendInvite`.
- **All bookings.** `listBusinessBookings`.

# Rules the app must show

- **R2 time zones.** Show both the customer's and the business's local times. A booking across a DST change shows its start and end in local time and its actual elapsed duration (e.g. 01:00-04:00, 2 hours, on a spring-forward night). TODO: layout.
- **R3 minimum notice.** On `MinimumNotice`, say how much notice the business needs (`minNoticeMinutes`). Staff and owners see the override option.
- **R4 rebook warning.** On `ConfirmationRequired` for a booking, show the original bookings that still stand; a customer booking for themselves is told to contact the business to cancel them.
- **R6 confirm before cancelling.** On `ConfirmationRequired` for time off, availability, a time zone change or removing staff, list the affected bookings and resend with `confirm.affectedBookingIds` only if the user confirms. If the list changed meanwhile, the API answers with the new list; show it again.
- **R7 conflict.** On `SlotConflict`, say the slot was just taken and refresh the slots. Never show details of the other booking (the API doesn't send them).

# Errors

How each `ErrorCode` is shown. The shared wording below is shown by one component (`shared/ui/ErrorMessage`, T33) in an alert (`role="alert"`); screens handle their own business-rule codes first and fall back to it. Wording decided in T33 (2026-11-26); screen tasks add theirs.

| Code | Shown as |
|---|---|
| `ValidationFailed` | Each entry in `details.fields` next to its field; `body` entries at the top of the form (T34 onwards) |
| `Unauthenticated` | Refresh the access token once (`refreshToken`, using the cookie); if that fails, back to login (T34) |
| `InvalidCredentials` | One message for a wrong email or password (T34) |
| `NotFound` | "We couldn't find what you were looking for." (the API answers 404 for anything the caller may not see) |
| `Forbidden` | "You don't have permission to do that." The caller can see it but may not do this (e.g. a customer changing staff); hide such actions in the first place |
| `SlotConflict` | See R7 |
| `ConfirmationRequired` | See R4 and R6 |
| `RequestRejected` 429 | "Too many attempts. Please wait a minute and try again." |
| `InternalError`, any other `RequestRejected`, a response without the Error shape, or an unexpected error in the app | "Something went wrong on our side. Please try again." and, when the response had an `X-Correlation-Id`, "If it keeps happening, quote reference {id}." |
| Network failure (no response) | "We couldn't reach the server. Check your connection and try again." |
| Any other code a screen doesn't handle | The API's own `message` |

A response without the Error shape (e.g. an HTML page from a proxy) counts as `InternalError` when it is 5xx and `RequestRejected` otherwise.
